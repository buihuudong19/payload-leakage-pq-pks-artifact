# Structural Payload Leakage in Post-Quantum Public-Key Image Steganography: code artifact

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24465712.svg)](https://doi.org/10.5281/zenodo.24465712)

This repository contains the implementation and the experiment pipeline of the article

> Dong Bui-Huu and Khuong Nguyen-An, *Structural Payload Leakage in Post-Quantum Public-Key Image Steganography*.
> Manuscript submitted to *Computers and Electrical Engineering*.

The article shows that a public-key stegosystem whose embedded payload is a standard ML-KEM-768 ciphertext can be
detected from the publicly extractable string alone, and proposes PQ-PKS, which encodes the encapsulation with
Kemeleon so that the extracted string is close to uniform. The code implements PQ-PKS, the baselines and reference
systems of the comparison, the wardens, and every experiment of the article (E1 to E7, the ablations and
the SRNet runs).

Release `v1.0.2` is the version used in the article. The badge above (concept DOI https://doi.org/10.5281/zenodo.24465712)
always points to the latest version; release `v1.0.0` is https://doi.org/10.5281/zenodo.24465713 and release `v1.0.1`
https://doi.org/10.5281/zenodo.24489200. Release `v1.0.1` added the post hoc lane W12 (`scripts/confirm/e1_posthoc_refit.py`);
release `v1.0.2` adds the steps registered after review (lane W13, `registrations/`) and the scripts that run them. In
every release nothing in `src/` or `configs/` changed; see [`CHANGELOG.md`](CHANGELOG.md). The raw measurement data are archived separately at https://doi.org/10.5281/zenodo.24487851
(version 1.1; see [Measurement data](#measurement-data)).

> **Research code.** The Kemeleon encoding is implemented with Python big integers and is not constant time.
> Do not use this code to protect real communication.

## Installation

Python 3.11 or later. The experiments of the article ran on Windows 11 with Python 3.12 environments created by
`scripts/confirm/setup_confirm.ps1` (CPU) and `scripts/gpu/setup_gpu.ps1` (GPU, PyTorch 2.8.0 with CUDA 12.6).
On any platform:

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -e .
python scripts/setup/fetch_third_party.py   # optional: module used by baseline BL4 (see third_party/README.md)
pytest -q
```

The confirmatory analysis also needs `sealwatch==2026.6`, `scikit-learn==1.9.1` and `matplotlib`; the SRNet runs need
the GPU environment of `scripts/gpu/requirements-gpu.txt`.

The functional tests run on synthetic test covers generated by `pqpks.data`, so they need no image data. Tests that
need an input which is not redistributed are reported as skipped, with the reason: the BL1 reference implementation
(`PQPKS_BL1_REFERENCE_DIR`) and the module of [Zha25] (`scripts/setup/fetch_third_party.py`). Tests that need `torch`, `sealwatch`, `jpeglib` or `matplotlib` are skipped
or fail at import when these packages are absent.

## Data

No image is redistributed. The experiments use BOSSbase 1.01, BOWS2-Original and ALASKA2, which must be obtained from
their providers under their own terms. `data/` contains the image lists, the frozen splits refer to these lists, and
the SHA-256 manifests let a user check that the downloaded images are the ones used in the article.
See [`docs/data.md`](docs/data.md).

## Reproducing the experiments

[`docs/reproduction.md`](docs/reproduction.md) lists every experiment with its command, its output and the table or
figure of the article that it produces. In short:

| Experiment | Main script | Results in the article |
|---|---|---|
| Analytic constants (Propositions 1-2, Lemmas 2M, 2R) | `scripts/theory/verify_constants.py` | constants of Sections 3-6 and of the supplementary material |
| E1, E1-bis: public syndrome of natural covers against uniform strings | `scripts/confirm/e1_confirm.py`, `scripts/confirm/e1bis.py` | E1 table and syndrome figure (Section 7) |
| E2/E3: wardens W-img, W-A0, W-pay, W-comb; TOST against REF-U; alpha* | `scripts/experiments/screen_run.py`, `scripts/confirm/analyze_confirm.py`, `scripts/confirm/apply_rules.py` | E2/E3 and TOST tables, D_pub, TPR and P_E figures (Section 7) |
| SRNet (gate G4 and confirmatory runs) | `scripts/gpu/srnet_train.py`, `scripts/confirm/srnet_evaluate.py` | SRNet rows of the E2/E3 and TOST tables |
| E4: functional correctness, tampering, replay, false alarms | `scripts/experiments/e4_functional.py` | E4 table (Section 7) |
| E5, E6: bit budget, capacity, time | `scripts/experiments/e5_budget.py`, `scripts/experiments/e6_perf.py` | capacity and timing tables, bit-budget figure (Section 7) |
| E7 and ablations (S2-S7) | `scripts/experiments/screen_run.py --plan {e7,ablate,ablate2,ra,confirm_r}`, `scripts/experiments/jpeg_run.py`, `scripts/confirm/phase_d.py` | supplementary tables |
| Image quality (PSNR, SSIM) | `scripts/analysis/quality_metrics.py` | discussion of image quality |
| Sensitivity of alpha* to the decision threshold (post hoc) | `scripts/analysis/alpha_star_thresholds.py` | threshold table of the supplementary material |
| Learned distinguisher D4 of E1 under the null and with model refitting (post hoc) | `scripts/confirm/e1_posthoc_null.py`, `scripts/confirm/e1_posthoc_refit.py` | post-hoc analysis of gate G3 (supplementary material) |

On the measurement machine (Windows 11, AMD Ryzen 7 3700X, 32 GB RAM, NVIDIA GeForce RTX 2060 SUPER 8 GB, about
250 GB of free disk) the whole confirmatory step is driven by

```powershell
powershell -ExecutionPolicy Bypass -File .\run_all.ps1 -DryRun   # walk through the step table without running anything
powershell -ExecutionPolicy Bypass -File .\run_all.ps1 -Reset    # full run
```

which opens one window per lane of `scripts/orchestration/pipeline.ps1` and a monitor window.

The steps added after the review of 24 November 2026 (G4 on fresh seeds, E1-ter on unused ALASKA2 images, receiver load
benchmark, a random-oracle bound on epsilon_valid, a clean-environment check) are listed in section 9 of
[`docs/reproduction.md`](docs/reproduction.md); their plans are in [`registrations/`](registrations/).

## Frozen profile

`configs/profile_frozen_v1.json` records the public parameters, the profile identifiers of the systems, the
pre-registered decision rules and the SHA-256 of every source file at the time the profile was frozen (5 November 2026,
before any confirmatory measurement). The confirmatory scripts refuse to run if `src/` or `configs/` differ from it.
The comments and messages of the code were edited for this release; `provenance/release_equivalence_v1.json` links
each edited file to its frozen hash, and `docs/provenance.md` describes the check.

## Measurement data

The raw measurement data of the article (per-cell warden scores, publicly extracted strings, E1 and E1-bis syndromes,
SRNet scores, result summaries) form the dataset `pq-pks-raw-data-v1`, archived on Zenodo under CC BY 4.0:
https://doi.org/10.5281/zenodo.24487851 (version 1.1, which adds the post hoc refit results of PH2; version 1.0:
https://doi.org/10.5281/zenodo.24462430). The record holds three archives with the same root folder `pq-pks-raw-data-v1/`:
`pq-pks-raw-data-v1-core.zip` (summaries, per-cover warden scores, SRNet models; enough to regenerate every table and
figure), `pq-pks-raw-data-v1-strings.zip` (publicly extracted strings) and `pq-pks-raw-data-v1-e1-syndromes.zip` (E1 and
E1-bis cover syndromes). Extracting all three into one folder gives the complete `results/` tree.

## Baselines

BL1 is the EC-ElGamal and MPVD system of an earlier implementation; its reference code is not redistributed, and the
tests and scripts that need it look for it in `baselines/bl1_reference/` or `PQPKS_BL1_REFERENCE_DIR`.
BL4 adapts the point encoding of [Zha25]; the original module is downloaded from its public repository and checked
against a SHA-256. See [`docs/baselines.md`](docs/baselines.md).
